# Commands

```bash
pnpm add -D @fairgarden/distribution   # provides fg-dist
```

Or run without installing: `pnpx @fairgarden/distribution <command>`.

## Setting up

- [`init`](/commands/init) — scaffold a distribution, monolith or module repository
- [`add-module`](/commands/add-module) — add a module repository as a submodule
- [`extract`](/commands/extract) — turn a directory here into its own repository

## Keeping it current

- [`sync`](/commands/sync) — what has moved, and whether the floor holds
- [`bump`](/commands/bump) — take the newest version of each module
- [`check`](/commands/check) — fail when this ships older than what it extends
- [`inherit`](/commands/inherit) — ship what the distribution this extends ships
- [`readme`](/commands/readme) — write the module versions into the readmes
- [`use-https`](/commands/use-https) — rewrite ssh submodule urls
- [`overrides`](/commands/overrides) — resolve modules from the tree, not the registry

## Forking a module

- [`fork`](/commands/fork) — check a module out from your fork, keeping its upstream
- [`contribute`](/commands/contribute) — push the change and open a pull request upstream
- [`unfork`](/commands/unfork) — go back to upstream once it has the fork's work

See [Forking a module](/overview/forking).

## The organization's policy

- [`policy`](/commands/policy) — build and test it, give each service its copy, and have turbo build it once

## Releasing a module

- [`workflows`](/commands/workflows) — give every module a publishing workflow and a changelog check
- [`changelog`](/commands/changelog) — check a pull request has its line; print a version's notes
- [`canary`](/commands/canary) — stamp a canary version, for CI
- [`release`](/commands/release) — open the next version on main, and a maintenance branch behind it
- [`prerelease`](/commands/prerelease) — start the next line on a branch, leaving main where it is

A module releases on its own schedule; see
[Releasing a module](/overview/releasing). A distribution others extend
publishes too — `workflows --distribution`, then `release` moves its version on;
see [Extending](/overview/extending#publishing-a-distribution).

## Shared options

| Option | Meaning |
| --- | --- |
| `--cwd <dir>` | repository to act on, default the working directory |
| `--dry-run` | report what would change without changing it |
| `--no-fetch` | use the refs already fetched, for offline or CI |

Mounting apps into one Next deployment is `fg-monolith`, in
`@fairgarden/monolith`.
